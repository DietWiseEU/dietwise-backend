# Intervention logging

## Problem

MyRecipeWatch shows a short motivational message, an Intervention, above the Suggestions of an assessed recipe. The
texts are curated by the marketing partners. Today the app picks one of five at random (`interventions.ts`), the texts
live in its i18n files, and the backend never learns which one was shown.

For the pilots (Grant Agreement O2, O6, KPI-26) the research partners must be able to tell how often each Intervention
was shown, to whom, and how users decided on the Suggestions while seeing it. Showing no Intervention is an arm of the
experiment and must be counted like the others.

The RCA must not be affected.

## Terms

- **Intervention**: a fixed motivational message, identified by a numeric id. Id `0` is the "no Intervention" arm.
  An id names one wording forever: a change of meaning is a new id, never an edit (typo fixes and translations are
  fine).
- **Intervention Assignment**: the Intervention the backend picked for one assessment, with the Suggestions shown
  under it. Identified by the `assessmentId`. "Assigned" is what is logged, not "displayed": if the app dies before
  rendering, the Assignment still counts (intention-to-treat).
- **Suggestion Event**: one accept/reject transition a user made on one Suggestion of an Intervention Assignment.

## Decisions

1. The backend picks the Intervention, per assessment, uniformly among the active Interventions (`0` included). No
   per-user stickiness, no motivational matching.
2. An Assignment is made only when the assessment request carries `uiLang`, there is at least one active Intervention,
   and the assessment produced Suggestions. Otherwise nothing is assigned or logged. The RCA and outdated app builds
   never send `uiLang`; deactivating every Intervention is a kill switch.
3. `DW_INTERVENTION` is the single source of the texts. The text is sent in `uiLang`, falling back to `en` when the
   Intervention has no text in that language. The app's i18n files no longer hold them.
8. `uiLang` is validated strictly: a blank value or a value outside the supported languages rejects the request, whereas
   a blank `lang` means `en`. A client must not send a UI language the backend does not support.
4. The Suggestion Events are an append-only log: one row per statistics call, never merged or overwritten.
5. `DW_USER_SUGGESTION_STATS` and the `/statistics/*` endpoints keep their behavior for every caller. The event is
   written in addition, in the same transaction as the counter, and even when the counter does not move (the
   `accepted + rejected ≤ suggested` cap, the floor at 0).
6. A statistics call with an `assessmentId` is validated strictly; on failure nothing is written, counters included.
7. Deleting an account deletes its Assignments and Suggestion Events, like the other statistics.

## Data model

New changelog `changelogs/20261022_interventions.xml`, included from `changelog.xml`.

`DW_INTERVENTION`, master data, no Working Copy:

- `id INTEGER` PK, assigned by hand (no sequence).
- `active BOOLEAN NOT NULL`.
- `text_en`, `text_nl`, `text_el`, `text_lt`, nullable `VARCHAR`. One column per language is a deliberate exception to
  the `*_TRANSLATION` tables, kept while the languages are few.
- `CHECK (id = 0 OR text_en IS NOT NULL)`, so the `en` fallback always exists.
- Seeded with `0` (all texts `NULL`) and `1..5`, copied verbatim from the `interventions` blocks of MyRecipeWatch's
  `en/nl/el/lt.json`, all active.

`DW_INTERVENTION_ASSIGNMENT`:

- `assessment_id UUID` PK, generated by the backend.
- `user_id UUID NOT NULL`, FK `DW_USER`.
- `application_id VARCHAR NOT NULL`.
- `intervention_id INTEGER NOT NULL`, FK `DW_INTERVENTION`.
- `ui_lang VARCHAR NOT NULL`: the language of the text actually sent (after the fallback to `en`); for `0`, which
  has no text, the `uiLang` of the request.
- `recipe_url VARCHAR`.
- `created_at TIMESTAMP NOT NULL`.

`DW_INTERVENTION_ASSIGNMENT_SUGGESTIONS`, the denominator of the acceptance rate:

- `intervention_assignment_assessment_id UUID`, FK `DW_INTERVENTION_ASSIGNMENT`; `suggestion_template_id UUID`, FK
  `DW_SUGGESTION_TEMPLATE`; composite PK.

`DW_SUGGESTION_EVENT`:

- `id UUID` PK.
- `intervention_assignment_assessment_id UUID NOT NULL`, FK `DW_INTERVENTION_ASSIGNMENT`.
- `suggestion_template_id UUID NOT NULL`, FK `DW_SUGGESTION_TEMPLATE`.
- `action VARCHAR NOT NULL`: `INCREASE_ACCEPTED`, `DECREASE_ACCEPTED`, `INCREASE_REJECTED`, `DECREASE_REJECTED`.
- `created_at TIMESTAMP NOT NULL`.
- Index on `intervention_assignment_assessment_id`.

The user and the Intervention of an event are reached through its Assignment. The final decision per (assessment,
Suggestion) is derived by replaying its events; no view is provided for now.

None of these tables is mirrored by the publish tool, so `Tables` does not change.

## Assessment

`RecipeAssessmentParam` and `RecipeExtractionAndAssessmentParam` gain an optional `uiLang`, a `UiLanguage`. It is a
type of its own, not a `RecipeLanguage`, because the languages of the user interface and of the recipes may differ.

In `RecipeAssessmentServiceImpl.assessSingleRecipe`, in the same transaction as `increaseTimesSuggested`, when decision
2 allows it: pick an active Intervention, insert the Assignment and its Suggestions, and resolve the text. The
transaction is opened by `RecipeAssessmentServiceImpl` and passed to both. If it fails, the failure is logged and the
assessment continues: the `SUGGESTIONS` message is sent without `assessmentId` and `intervention`.

`SuggestionsRecipeAssessmentMessage` gains optional fields, absent when nothing was assigned:

- `assessmentId`
- `intervention`: `{ id, text }`; `text` is `null` for `0`.

The random pick is behind a small injectable seam, so that tests can fix it.

## Statistics

`StatisticsParam` gains an optional `assessmentId`. Without it, the four `/statistics/*` endpoints behave exactly as
today. With it, after validation, the service updates the counter as today and appends one `DW_SUGGESTION_EVENT`, in
one transaction.

Validation, before anything is written:

- The Assignment does not exist, or belongs to another user or application: `EntityNotFoundException` (`404`).
- The Suggestion is not among the Assignment's Suggestions: `InvalidRequestException` (`400`).

## Account deletion

`AccountServiceImpl.deleteLocalAccountData` also deletes, in this order, the user's Suggestion Events, Assignment
Suggestions and Assignments.

## MyRecipeWatch

- Send `uiLang` (the i18n language) with the assessment request.
- Show the banner if and only if the `SUGGESTIONS` message carries an Intervention with a non-null text.
- Keep the `assessmentId` with the assessment state and send it with every statistics call of that assessment.
- Remove `interventions.ts`, its test, and the `interventions` blocks of the i18n files.

## RCA

No change. Verified against its request shapes and tests: it sends neither `uiLang` nor `assessmentId`.

## Rollout

Backend first; it is backward compatible. MyRecipeWatch follows. Until then, no Assignment is made.

## Assumptions to confirm with the research partners

- Equal probability for every arm, "no Intervention" included.
- Per-assessment randomization: the same user sees several arms, so the analysis must account for repeated measures
  (e.g. a mixed model with the user as random effect).
- Users who delete their account leave the dataset.
